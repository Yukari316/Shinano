# NB2Bridge 插件约定

插件 ID `nb2-bridge`。通用约定见仓库根目录 `AGENTS.md`；本文件只记录本插件的业务规则。

- NB2Bridge 接入由 Shinano 管理的 NoneBot2 服务进程。该服务承载多个可信 NoneBot2 插件，提供 HTTP API 管理在线启用和禁用。多平台解析使用 `https://github.com/fllesser/nonebot-plugin-parser`，覆盖其支持的平台和内容，尽量保留原生行为，配置通过 NB2Bridge 扩展的页面管理。
- 可托管的 NoneBot2 插件同样必须经管理员人工认可；尽量保留其原生行为。NoneBot2 插件管理页提供上传/删除、启用/停止、运行监控和统计数据；NB2Bridge 读取各插件 `PluginMetadata.config` 的 pydantic 模型 JSON Schema 生成通用配置表单，校验后写回 `.env`，提示重启 NB2 服务生效；未声明配置模型的插件显示无可配置项。主框架不为任意第三方插件生成表单。
- NB2 运行环境由工具子命令 `nb2-setup`（初始化时可选执行）用 uv 在部署数据目录的 `nb2/` 创建独立 venv，固定 Python 3.12，安装固定版本的 nonebot2、Milky 适配器与 nonebot-plugin-parser，写入初始插件配置 `.env`、插件清单 `plugins.json` 与依赖锁定文件；NB2Bridge 不自行创建，缺失时在页面与日志提示。插件按 PyPI 包名与版本或上传 wheel 安装，NB2Bridge 停止服务后执行 `uv pip install`/卸载并确认模块可导入，再恢复原来的运行状态，失败时按锁定文件（`uv pip sync`）还原；新装插件默认不响应事件，卸载不清理共用依赖。
- `NB2Bridge` 管理 NB2 服务进程的启动、停止、重启、消息/事件转换、管理 API 和 Web UI 页面。NB2 服务不在运行中添加或删除插件；NB2Bridge 停止进程后完成包变更，再启动进程。NB2 进程随 NB2Bridge 启用而启动、停用而停止（宿主经插件启停回调通知）；每次启动前从插件包覆盖 `bot.py` 与控制插件，进程级配置（监听地址、Milky 连接、SUPERUSERS、加载的插件、localstore 目录、前置 ffmpeg 目录的 PATH）全部经环境变量传入并集中在 `Nb2Environment` 定义，页面列出本次传入的变量（token 只显示已设置），`.env` 只放插件配置。NB2Bridge 在 127.0.0.1 随机端口扮演 Milky 实现端，NB2 以官方 Milky 适配器的客户端模式连接，token 每次启动随机生成；控制插件在 NB2 的 HTTP 服务 `/shinano/` 下提供插件列表与统计、禁用集合、正常关停，并提供 `nb2ping` 指令（回复 `pong`）。意外退出自动重启，1 分钟内超过上限（默认 3 次）停止并通知 Super User 一次（`NB2-STOPPED`）；停止先经控制 API 正常关停，超时（默认 10 秒）强制结束；控制插件失去连接 60 秒后自行退出。进程输出写入 `nb2/logs/` 按大小轮转。NB2 的健康只由 NB2Bridge 监视并显示在其页面，不计入宿主健康状态；Super User 可用「NB2状态」取得状态报告卡片。
- NB2 在线禁用停止新的消息/事件响应，取消该插件等待中的连续对话，已经开始的处理允许结束。定时任务和后台工作仅在插件提供明确暂停能力时一起暂停，否则管理页显示为仅暂停事件响应。
- NB2Bridge 作为一个整体参与主框架普通事件订阅链，到达后才向 NB2 服务交付对应事件。NB2 服务内不提供插件排序，原生 matcher 保持全局优先级、同级并发和阻断语义。
- 消息处理的继续/终止：NB2 有 matcher 确实开始处理该事件（权限、规则与全部运行前处理器都已放行，进入 `Matcher.run`）时立即回报终止，不等处理结束，主框架事件链随之终止；其他情况（没有 matcher 开始处理、未连接、交付失败、等待超时，默认 5 秒、可配置）一律继续。回报按 NB2Bridge 附在事件上的 `shinano_key` 关联。交付的事件类型由 NB2Bridge 配置选择，默认只交付群聊与好友私聊消息，通知与请求默认不交付；临时会话的用户不是服务对象，其消息与事件一律不交付。服务不可用或等待超时时记录日志并继续主链，不自动重新提交已交付事件，超时后才到达的回报记录警告；超时不能作为 NB2 已取消处理的证据，后续发送仍按实际结果归档。
- NB2 的发送及其他平台动作经桥接回到 Shinano 执行：群聊与私聊发送转为 Sora 发送，成功后由宿主记录器归档；其他动作由宿主以自己的 LLBot 配置原样转发并原样返回；NB2 发送的本地文件（`file://`）先上传到插件 bucket（用途 `nb2`）换成预签名链接，只处理 adapter 用于文件地址的字段（图片、语音、视频消息段的 `uri` 与视频的 `thumb_uri`，含合并转发内嵌的段；`set_avatar`、`set_group_avatar`、`send_group_announcement`、`upload_private_file`、`upload_group_file` 的文件地址参数），文本等其余字段中的 `file://` 原样转发，避免复读群友输入时读取本机文件；对象保留 1 小时供归档读取后由每小时的清理任务删除。自身消息回报全部排除。管理 API 限本地受认证访问，不向前端暴露 LLBot 凭据。
- NB2 插件配置在保存时校验并明确生效状态。支持原生热更新的配置即时应用；导入时读取的配置由 NB2Bridge 重启 NB2 服务后应用，重启影响服务内全部插件。
