# NB2Bridge 插件约定

插件 ID `nb2-bridge`。通用约定见仓库根目录 `AGENTS.md`；本文件只记录本插件的业务规则。

- NB2Bridge 接入由 Shinano 管理的 NoneBot2 服务进程。该服务承载多个可信 NoneBot2 插件，提供 HTTP API 管理在线启用和禁用。多平台解析使用 `https://github.com/fllesser/nonebot-plugin-parser`，覆盖其支持的平台和内容，尽量保留原生行为，配置通过 NB2Bridge 扩展的页面管理。
- 可托管的 NoneBot2 插件同样必须经管理员人工认可；尽量保留其原生行为。NoneBot2 插件管理页提供上传/删除、启用/停止、运行监控和统计数据；NB2Bridge 读取各插件 `PluginMetadata.config` 的 pydantic 模型 JSON Schema 生成通用配置表单，校验后写回 `.env`，提示重启 NB2 服务生效；未声明配置模型的插件显示无可配置项。主框架不为任意第三方插件生成表单。第三方 NB2 插件的配置（含其中的 API key 等）按整体编辑，配置对话框明文显示 `.env` 中的当前值：它们由管理员填写、只在登录后的面板中可见，不属于宿主"只写不回显"的机密。
- NB2 运行环境分两层固定依赖。**NB2 基础环境**：只含 NB2 直接运行所需的 nonebot2 与 Milky 适配器（`bot.py` 与控制插件只用到它们），由随插件包发布的期望基础锁定文件 `assets/nb2/base.lock`（跨平台、带哈希、禁止预发布版，由 `build/nb2-lock` 生成，同时生成以它为约束的初始插件锁定 `initial-plugins.lock`，并在临时 venv 中实际加载验证）固定；**插件层**：全部 NB2 插件的依赖闭包，每次变更通过试加载后按已安装版本生成带哈希的 `nb2/plugins.lock`。修改 `base.lock`（或 `initial-plugins.lock`）必须同时提高本插件 `plugin.json` 的版本号，否则升级时随包插件不会更新。
- 工具子命令 `nb2-setup`（初始化时可选执行）只负责首次建立：检查 uv 不低于 0.5.0，从已安装的 NB2Bridge 读取期望基础锁定文件，用 uv 在部署数据目录的 `nb2/` 创建 Python 3.12 venv 并带哈希同步基础环境，复制为实际基础锁定文件 `nb2/base.lock`，写入初始插件配置 `.env` 与插件清单 `plugins.json`（parser，默认不启用）；venv 已存在时不改动依赖。NB2Bridge 不自行创建 venv，缺失时在页面与日志提示。
- 期望值与实际值的关系决定环境状态：一致且已有插件层锁定为正常；一致但没有插件层锁定（刚由 `nb2-setup` 建立）时，启动 NB2 前自动重建一次以安装插件层；实际值与期望不同（NB2Bridge 升级带来新版）或缺失（旧版建立的环境）时，在页面、「NB2状态」与启动日志中建议重建，照常启动 NB2，但禁止安装与升级插件，卸载照常。
- 重建（页面按钮，与首次建立后的自动重建相同）：基础层带哈希同步；基础层未变且插件层已锁定时按两份锁定文件精确同步；插件层尚未锁定时安装插件清单，parser 版本与随附锁定一致则按其锁定安装；基础层已变时先以旧插件层中不属于新基础层的版本为约束安装，失败或试加载失败再去掉旧版本约束重新解析，结果列出插件层版本变化；最终失败时整体还原。
- 插件按 PyPI 包名与版本或上传 wheel 安装：NB2Bridge 停止服务后执行 `uv pip install`，以实际基础锁定、插件层已锁定的版本（不含正在安装或升级的插件本身）与管理员约束（`nb2/constraints.txt`，在页面编辑，只允许包名、版本条件、环境标记与注释）为约束并禁止预发布版，使基础层与已验证插件的依赖都不被改变；与已装插件冲突时可由管理员确认「允许调整已装插件的依赖后重试」，去掉插件层版本约束并列出版本变化；上传与已装 wheel 同名（即同一版本）的文件会被拒绝，需先卸载或换版本号，因为插件层锁定按路径与哈希记录已装的 wheel。安装、卸载与重建后都在一个进程中试加载全部插件（`bot.py` 的试加载模式，localstore 指向临时目录，读取真实 `.env`），失败即还原：有两份锁定文件时按它们带哈希同步，否则按变更前的 `uv pip freeze` 同步。完成后恢复 NB2 原来的运行状态；新装插件默认不响应事件，卸载不清理共用依赖。不使用冷却期等推迟问题的手段：上游新发布的版本导致组合不可用时，由试加载发现、由锁定文件保持已验证的组合、由管理员约束显式排除。
- `NB2Bridge` 管理 NB2 服务进程的启动、停止、重启、消息/事件转换、管理 API 和 Web UI 页面。NB2 服务不在运行中添加或删除插件；NB2Bridge 停止进程后完成包变更，再启动进程。NB2 进程随 NB2Bridge 启用而启动、停用而停止（宿主经插件启停回调通知）；每次启动前从插件包覆盖 `bot.py` 与控制插件，进程级配置（监听地址、Milky 连接、SUPERUSERS、加载的插件、localstore 目录、前置 ffmpeg 目录的 PATH）全部经环境变量传入并集中在 `Nb2Environment` 定义，页面列出本次传入的变量（token 只显示已设置），`.env` 只放插件配置。NB2Bridge 在 127.0.0.1 随机端口扮演 Milky 实现端，NB2 以官方 Milky 适配器的客户端模式连接，token 每次启动随机生成；控制插件在 NB2 的 HTTP 服务 `/shinano/` 下提供插件列表与统计、禁用集合、正常关停，并提供 `nb2ping` 指令（回复 `pong`）。意外退出后间隔 20 秒自动重启，自上次就绪（或手动启动）起最多重启 2 次，就绪后计数清零；第 2 次重启后仍意外退出或无法启动时停止拉起并通知 Super User 一次（`NB2-STOPPED`），之后由管理员手动启动；等待重启期间手动启停或包变更会取消这次重启（包变更完成后直接启动）；停止先经控制 API 正常关停，超时（默认 10 秒）强制结束；控制插件失去连接 60 秒后自行退出。进程输出写入 `nb2/logs/` 按大小轮转。NB2 的健康只由 NB2Bridge 监视并显示在其页面，不计入宿主健康状态；Super User 可用「NB2状态」取得状态报告卡片。
- NB2 在线禁用停止新的消息/事件响应，取消该插件等待中的连续对话，已经开始的处理允许结束。定时任务和后台工作仅在插件提供明确暂停能力时一起暂停，否则管理页显示为仅暂停事件响应。
- NB2Bridge 作为一个整体参与主框架普通事件订阅链，到达后才向 NB2 服务交付对应事件。NB2 服务内不提供插件排序，原生 matcher 保持全局优先级、同级并发和阻断语义。
- 消息处理的继续/终止：NB2 有 matcher 确实开始处理该事件（权限、规则与全部运行前处理器都已放行，进入 `Matcher.run`）时立即回报终止，不等处理结束，主框架事件链随之终止；其他情况（没有 matcher 开始处理、未连接、交付失败、等待超时，默认 5 秒、可配置）一律继续。回报按 NB2Bridge 附在事件上的 `shinano_key` 关联。交付的事件类型由 NB2Bridge 配置选择，默认只交付群聊与好友私聊消息，通知与请求默认不交付；临时会话的用户不是服务对象，其消息与事件一律不交付。选中的事件再按 NB2 响应范围过滤：群聊与好友私聊各自选择白名单或黑名单，在 NB2 页面从 Bot 当前的群与好友列表勾选（已不在的号码保留可取消），默认为空黑名单即全部交付，空白名单不交付该类任何会话；群内消息、通知与入群申请按群号判断，好友消息与通知按好友 QQ 号判断，好友申请与入群邀请不受限制；对 Super User 同样生效，不限制 NB2 主动发送；范围存于全局 schema、不按账号区分，保存即时生效，范围外的事件不记日志。服务不可用或等待超时时记录日志并继续主链，不自动重新提交已交付事件，超时后才到达的回报记录警告；超时不能作为 NB2 已取消处理的证据，后续发送仍按实际结果归档。
- NB2 的发送及其他平台动作经桥接回到 Shinano 执行：群聊与私聊发送转为 Sora 发送，成功后由宿主记录器归档；其他动作由宿主以自己的 LLBot 配置原样转发并原样返回；NB2 发送的本地文件（`file://`）先上传到插件 bucket（用途 `nb2`）换成预签名链接，只处理 adapter 用于文件地址的字段（图片、语音、视频消息段的 `uri` 与视频的 `thumb_uri`，含合并转发内嵌的段；`set_avatar`、`set_group_avatar`、`send_group_announcement`、`upload_private_file`、`upload_group_file` 的文件地址参数），文本等其余字段中的 `file://` 原样转发，避免复读群友输入时读取本机文件；对象保留 1 小时供归档读取后由每小时的清理任务删除。自身消息回报全部排除。管理 API 限本地受认证访问，不向前端暴露 LLBot 凭据。
- NB2 插件配置在保存时校验并明确生效状态。支持原生热更新的配置即时应用；导入时读取的配置由 NB2Bridge 重启 NB2 服务后应用，重启影响服务内全部插件。
