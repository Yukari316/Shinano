# B站订阅插件约定

插件 ID `bilibili`。通用约定见仓库根目录 `AGENTS.md`；本文件只记录本插件的业务规则。

- 整个部署只登录一个 B站账号，与 Bot 的 QQ 账号无关，切换 Bot 账号后不变。登录由宿主浏览器服务维护：扫码得到的登录状态注入插件的浏览器用户目录，启动时与每天一次用浏览器打开 B站首页，由网页前端自行检查与刷新登录、生成风控 Cookie，再把 Cookie 与浏览器 UA 导出给普通 HTTP 读取；插件不自行实现签名、指纹与 Cookie 刷新，登录状态以浏览器用户目录为准，Web 只显示登录状态。
- 扫码登录可在插件 Web 页进行，也可由 Super User 私聊「B站登录」触发（群聊不响应），二维码私聊发给触发者，180 秒过期；成功、过期、失败各回复一次，过期与失败提示重新触发。已登录时先显示原账号昵称与 UID 并等待触发者回复 `y`/`n`（不区分大小写，其他消息不消耗，等待时间可配置，默认 60 秒）；`n` 与超时明确回复已取消；`y` 时在浏览器中退出原账号使其失效，再清空用户目录并开始新登录。面板登录同样先确认（使用面板自己的对话框）。登录已失效时不确认，直接清空原账号的登录数据。
- 动态来自登录账号的关注流（`feed/all/update` 判断有无更新，`feed/all` 翻页至推送进度），以能取得的关注列表为准：关注由用户在 B站自行维护，插件不关注、不取关。关注列表按 B站账号记录，面板只在已登录时显示当前账号关注的 UP 与最近动态时间；按 UP 设置是否推送动态、直播（可只推一种）与推送的群，新关注默认不推送。推送设置按 UP 保存：换号后保留，新账号也关注的 UP 自动沿用，从当时开始推送、不补推未关注期间的动态；登录账号取关的 UP，推送设置与推送进度重置为新关注的初始状态，避免之后换号时被误推送。关注列表每小时与打开面板时刷新；轮询间隔可配置，默认 10 分钟。
- 订阅设置与推送进度按 Bot 账号隔离，推送进度按群与 UP 记录。每轮推送进度之后的全部新动态（跳过置顶与直播推荐动态），每个 UP 每轮最多 3 条，按发布时间先后；没有推送进度的订阅首次推送当前最新一条。一条动态由卡片与「附加内容」合并转发组成，附加内容依次为正文截断时的「原文太长了喵！要坏掉了喵！\n<原文链接>」、动态内的图片（每张一个节点）、视频的封面原图与 BV 号，没有时省略。每个群、每个 UP 本轮只有一条动态时，先直接发卡片，再发附加内容，以卡片发送成功为准，附加内容失败只记日志不重试；多条时为一条合并转发：第一、二条为纯文本「<UP名>更新了喵」「一共<n>条动态喵」，之后每条动态为卡片与嵌套的附加内容。节点发送者不用 Bot 身份：昵称为 UP 名，QQ 号取插件配置（默认 114514）。以上方式发送失败且 LLBot 仍连接时，立即改发一条纯文本合并转发（单条与多条相同）：第一条为「<UP名>更新了喵」，之后每条动态一个文字节点「<UP名><动作>：<正文>」，正文超过 500 字截断并以「……」结尾，不含图片、卡片与链接。首选方式或纯文本降级发送成功后才推进该群的进度；未连接 LLBot 或降级也失败时不推进，下一轮重试。本轮有群未送达时保留关注流的更新基线，下一轮重新读取关注流；一个 UP、一个群的推送出错不影响其他推送。原图节点直接使用 B站图片地址，由 IM 端下载。
- 动态由插件使用 SkiaSharp 自行绘制为卡片图片，风格与宿主卡片相同（宿主外框，插件绘制内容区），不附带链接：图文、专栏与纯文字为正文与缩略图，视频为封面、标题、简介、时长与 BV 号，转发为转发内容连同原动态的一张卡片，其他类型用通用排版，附加卡片（投票、预约等）为一行「类型：标题」。缩略图与 B站一样为正方形（长图取顶部），2、4 张两列，其余三列，最多 9 格并在第 9 格标出剩余数量；单张图按卡片宽度完整缩放，高度最多为宽度的 2 倍，超出取顶部。正文按排版后的行数截断并以「……」结尾，上限按类型在插件配置中设置（图文与纯文字、专栏摘要、其他类型默认 20 行，转发内容与原动态各自默认 10 行，视频简介默认 3 行）；正文被截断时附加内容带原文链接 `https://t.bilibili.com/<动态ID>`（只有原动态被截断时指向原动态），专栏在卡片中只有摘要，总是附带；视频简介截断不附带。
- 直播状态每轮一次批量查询（不需要登录），直播中以外（含轮播）都视为未开播；开播只发纯文本「<UP名> 直播了喵\n<直播间链接>」，下播只发「<UP名> 下播了喵！\n播了<时长>喵」（「X小时Y分钟」，不足 1 小时省略小时，不足 1 分钟为「不到1分钟」）。首次查询时正在直播则发开播。
- 未登录或登录失效时暂停动态轮询；登录失效时直播照常按失效前账号的关注推送，失效时通知 Super User 一次（进程重启后不重复）；主动退出后不推送，直到重新登录。遇到风控码时暂停 1 小时，再用浏览器刷新登录信息与 Cookie 后恢复；风控开始与恢复各通知 Super User 一次。
