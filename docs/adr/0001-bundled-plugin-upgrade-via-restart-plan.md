# 随包插件升级经由重启计划在首次启动时应用

Status: accepted

## Context

`Shinano.Tool upgrade` 在停机窗口内替换宿主、监控与随包插件归档（`bundled-plugins/`）。对于部署中已安装的随包插件，若新发布包含有更高版本号的插件包，面临三种处理方式：仅放入待处理插件变更区等待管理员再去管理面板重启；在停机期间直接原地覆盖 `data/plugins/`；或由工具暂存新包并同时写入 `data/restart/plan.json`，交由升级后首次启动的宿主应用。

## Decision

升级工具在停机窗口内暂存更高版本的随包插件，并直接写入宿主重启计划（`data/restart/plan.json`），使升级后首次启动的宿主在加载插件前自动完成替换、加载验证，并在加载失败或超时未就绪时自动回滚到上一套插件包。

- 仅将本次随包插件的升级纳入该重启计划，不吞入管理员在管理面板手动暂存的其他插件变更，也不覆盖同一插件已有的手动暂存。
- 从未装入过的新增随包插件仍直接装入 `data/plugins/` 且默认不启用，不纳入重启计划。
- 升级前若已存在未完成的 `data/restart/plan.json`，工具直接中止并提示先启动旧宿主完成应用或回滚，不覆盖现场。

## Considered Options

- **仅暂存等待面板手动重启**：升级后首次启动运行“新宿主 + 旧插件”，容易因宿主/框架变更引发隐蔽错配，且管理员易误以为升级已完成。
- **停机期间直接原地覆盖 `data/plugins/`**：实现最简单，但放弃了宿主启动后的插件加载验证与自动回滚能力，坏插件会导致部署降级且无法自动恢复。

## Consequences

- `Shinano.Tool` 与 `Shinano.Host` 共享 `data/restart/plan.json` 和 `data/restart/result.json` 的结构契约，需由契约测试持续保证一致。
- 直接运行守护进程在首次启动宿主前也需检查 `data/restart/plan.json`，存在时即启用未就绪杀进程再拉起回滚的看护模式。
- 服务模式升级在宿主就绪后需核对 `data/restart/result.json`，如发生回滚或未验证则明确报告原因并以非零退出码结束。
