# Shinano.Host 约定

通用约定与高频硬规则见仓库根目录 `AGENTS.md`；本文件记录宿主运行时、插件框架、基础能力与健康通知的完整规格。

## 宿主运行边界

- 主工程承载插件生命周期、公共基础能力和 Web 管理，不内置业务功能；健康检查属于宿主运维能力。
- 使用 ASP.NET Core 同进程托管 Bot、管理 API 和前端，使用 Autofac 管理依赖。数据库或 RustFS 启动检查失败时 Bot 不上线，管理面板继续提供故障与日志查看能力。
- 使用 Milky 协议，协议端（如 LLBot）的地址、路径前缀与 AccessToken 由部署配置提供；开发端不报告自身消息。
- 一个进程只连接一个 Milky 机器人账号，以 `self_id` 标识；停止后可切换账号再启动，其余部署配置保持不变。

## 插件框架与生命周期

- 业务功能按以下插件划分，每个插件是一个启停单位：有人问（`plugins/Shinano.Plugin.Qa`）；B站订阅（`Bilibili`）；搜图（`ImageSearch`）；Hso（`Hso`）；娱乐（`Entertainment`）；切噜（`Cheru`）；在线检测（`OnlineCheck`）；NB2Bridge（`NB2Bridge`，接入由 Shinano 管理的 NoneBot2 服务）；Gemini 对话（`Gemini`）。搜图与 Hso 共用类库 `plugins/Shinano.Plugin.ImageSources`。
- 自定义模块拆分为独立工程，实现基础框架的插件接口。插件负责声明服务、数据库初始化、Filter、特性指令、事件订阅和后台任务，统一由宿主的插件注册及响应控制 API 管理其归属和启停，不在每个处理器中重复判断使能标志。后台任务通过宿主调度器登记，插件停用后宿主不再触发，正在执行的一次允许完成；插件不得自建不受管理的定时器。
- 插件默认不启用，通过 Web UI 启用。有可配置项的插件必须定义默认配置并支持管理界面修改；没有可配置项的插件不声明配置类型，其页面显示无可配置项。
- 插件包以单个 zip 上传，包含 `plugin.json`、程序集、可选的 `web/` 前端资源与 `assets/` 素材；每个插件使用独立 AssemblyLoadContext，并共享宿主契约程序集、Sora、SkiaSharp（含 HarfBuzz）与 PuppeteerSharp。插件不实现停用方法，停用由宿主统一完成。
- 仅运行经管理员人工认可来源及代码的可信进程内插件，插件拥有 Bot 进程权限，不提供不可信代码沙箱。原生插件首次使用时加载 DLL 并按特性自动登记指令，停用保留程序集、实例和配置表单，由统一 API 停止业务响应；重新启用复用已有登记，避免重复扫描与注册。
- 插件包的上传、删除和升级不在运行中卸载程序集，而在进程重启后生效；重启由守护者拉起新进程，管理面板在重启后自动恢复连接，不需要登录服务器手动操作。主进程一律以约定退出码 `75` 退出，由守护者重启：直接运行时为前台的 `Shinano.Tool run`，由 systemd 或 Windows 服务托管时为服务管理器；不经守护直接运行宿主时重启只会退出。
- `Shinano.Tool run` 下新进程 60 秒内未就绪时结束它并再启动一次，由宿主还原上一套插件包；就绪指进程开始监听、启动流程结束且本次变更的插件包全部加载成功，插件初始化不计入，数据库不可用导致的故障模式不触发回滚。暂存的插件包变更只由面板的重启操作应用，普通启动不自动应用；面板列出全部待处理变更（安装、升级含新旧版本、删除）并可逐项撤销，启动日志同样列出。升级允许降级。
- 删除插件包时提供是否同时清除插件数据的选项，选择清除需二次确认（第二个对话框列出将删除的表、bucket、机密文件与浏览器用户目录），待处理变更中显示为「删除并清除数据」，重启前可撤销；清除在重启确认成功、基础设施就绪后于后台执行，回滚则不清除，范围为声明的表与结构版本记录、持久媒体引用、声明的全部 bucket、配置与启用状态、机密文件与浏览器用户目录，失败的步骤下次启动重试（通知 Super User 一次，`PLUGIN-PURGE-FAILED`），执行前发现同 ID 插件已重新安装则放弃剩余步骤；表只按声明的表名全字匹配删除，清除后名字以插件前缀开头（ID 原样或 `-` 换 `_`，接 `_` 或 `-`，不区分大小写）但未声明的表列为「可能的残留」，不删除。插件管理页为每个被清除的插件显示一条结果，逐项列出删除数量。登录会话签名密钥持久化到本地，重启后无需重新登录；管理面板提供通用重启操作，用于需要重启生效的配置。
- 原生插件的使能由宿主统一控制，停用指令在匹配、重入及阻断之前完全跳过，不占用消息，后续指令和普通事件继续执行。`CommandBeforeFilterAttribute` 仅用于已启用插件的执行前业务拦截；插件使能不通过该 Filter 控制。
- 使能通过 Sora 的程序集登记实现：一个插件对应一个登记程序集，指令与动态指令只在插件主程序集声明。首次启用按 `RegisterAssembly(enabled: false)`、注入 Autofac 构造的指令实例、`ScanCommandGroups()`、完成插件初始化、`SetEnabled(true)` 的顺序执行；之后启停只调用 `SetEnabled`，不使用类型级开关。机器人账号就绪前启用只持久化，账号就绪后统一激活；账号或插件初始化失败时不定时重试，而在 LLBot 重新连接、数据库或 RustFS 恢复以及管理员重新启用时重试，重试保留程序集登记，先丢弃插件上次登记的事件订阅、后台任务、页面、API 与启停回调。启停从下一条消息生效，正在分发的那条消息视为已开始的处理；正在等待连续对话的处理器同样属于已开始的处理，停用后宿主不取消，由其自身超时结束（Sora 未指定时默认 1 小时）。
- 管理页只展示指令的类型级状态与数量，不列出逐条指令。
- 管理页只有一个插件顺序，同时决定 Sora 程序集优先级（跨插件指令顺序）和普通事件订阅链顺序；指令自身优先级只在插件内部生效。Sora 先处理全部指令，再分发普通事件。某个处理器终止事件链后，不执行后续订阅者，包括尚未到达的 NB2Bridge。
- 每个插件在管理面板侧边栏占用独立的选项卡页面，不与其他插件共用页面。简单配置项使用宿主按配置类型生成的通用表单；只有存在复杂业务逻辑时才编写插件专用前端页面。插件作者将页面预先构建为浏览器可加载的 JS/CSS，随插件交付，由宿主按同源资源加载并登记/清理导航和页面。NB2Bridge 自行提供 NB2 管理和配置页面，原 Python 插件不要求自带 Vue 资源。
- 插件面板分两类，插件可以只提供其一或两者都有，由插件设计者取舍：配置表单由插件在加载后通过 `ConfigurePanel` 声明配置类型，宿主按类型生成通用表单，与启停无关，插件加入后即可显示和修改；专有面板（插件 `web/` 前端页面与插件管理 API）在插件启用时加入面板，停用时移除，停用期间其页面与 API 不可访问，包括 NB2Bridge。只有表单项很多且另有复杂配置逻辑的插件才同时提供两类。面板接口均按面板认证授权。
- Bot Super User ID 列表来自部署配置，切换机器人账号后继续生效，并同步到 NB2；具备所有插件的可执行权限。Super User 权限不启用已停用插件，也不能绕过 IM 平台或操作系统本身的限制。Sora 的 `PermissionLevel` 是 IM 成员角色，`IsSuperUser` 是 IM 之外的用户标记，Sora 不让后者绕过前者；Shinano 插件指令在 Sora 中声明为 Member 级，由宿主提供的 `[RequirePermission(MemberRole)]` 特性先放行 Super User，再在群聊检查 IM 成员角色；私聊没有 IM 角色，要求高于 Member 时非 Super User 一律拒绝。拒绝时不回复，指令已命中故消息被占用。仅限 Super User 的指令使用 Sora 原生 `SuperUserOnly`。NB2 侧同步 SUPERUSERS 列表，第三方 NB2 插件的自定义权限逻辑不保证统一接管。
- GsCore 后续通过独立 Shinano 插件实现桥接，目前不实现其运行端、插件管理或 WebConsole 接管。
- 抽老婆和网页截图属于后续重做范围；MoeGoe、公会排名、聊天内状态指令、全群广播及公主连结公会战管理不实现。

## 宿主公共基础能力

### 公共字体与消息图片渲染
- 宿主提供公共字体（Noto Sans SC 常规与粗体、Saira Expanded 中粗与粗体、JetBrains Mono、Twemoji Mozilla 彩色 emoji）、带字体回退与 HarfBuzz 整形的文字绘制辅助，以及统一风格的消息图片：白底工业编辑风（参考《终末地》，色值为宿主具名色板，与面板 daisyUI 主题无关），墨色反转标题块加黄色斜楔、带取景角的白色面板，等级只由菱形状态标与标签颜色表示，页脚左右两侧的文字是否填写由调用方决定，卡片的每一行由调用方选择显示为一段文字或多个元素（可为每个元素画方框）；分通知、列表、排行、信息卡、状态报告与 Markdown 文档六类，另提供只绘制外框、内容区由插件绘制的框架卡片，文档的图片可内嵌或单独发送、链接默认只显示文字。按 720 宽排版，输出宽度由部署配置决定（默认 1200 像素），高度随内容增长。需要这类图片的功能直接使用，有自己风格的功能自行绘制；公共字体不够用的插件自行在 `assets/` 中提供字体。

### 无头浏览器基础服务（PuppeteerSharp）
- 供需要真实浏览器维护登录或风控状态的插件使用：按需启动、会话结束即关闭，同一插件的会话串行；每个插件独立的持久用户目录位于部署数据目录，视同机密，管理员清除插件数据时删除。
- 浏览器为下载到部署数据目录的 Chrome for Testing，版本在宿主配置中选择最新稳定版（默认，每天最多解析一次，有新版即下载并删除旧版）、PuppeteerSharp 固定版本或指定主版本号，也可指定本机浏览器路径；每个页面把 UA 与 Client Hints 覆盖为同版本正式版 Chrome 的值并去掉自动化标记；Linux 一律以 `--no-sandbox` 运行。浏览器不计入启动检查与健康状态，不可用时只表现为使用它的插件报错。

### ffmpeg 基础服务
- 插件经 `IPluginTools` 取得含 `ffmpeg`、`ffprobe`、`ffplay` 的目录。来源在宿主配置 `Shinano:Ffmpeg` 中选择：自动下载（默认，从 FFmpeg-Builds 下载宿主固定版本分支的静态构建到部署数据目录 `ffmpeg/`，按发布附带的 SHA256 校验后用系统 `tar` 解压，只在缺失或版本分支变化时下载）、系统 `PATH` 或指定目录；后两种须三个程序在同一目录。三个程序都确认可运行才算可用；首次使用时解析，失败不缓存。不计入启动检查与健康状态。

## 健康检查与 Super User 通知

- 服务健康分正常、降级、停止三级，对应 daisyUI 语义色 `success`、`warning`、`error`：数据库离线、启动故障模式、LLBot 断线为停止；RustFS 离线、有插件初始化失败为降级；其余为正常。整体状态取各项中最差的一级。
- 运行中数据库离线时记录错误日志并通知全部 Super User，Bot 关闭全部插件程序集以停止响应全部功能直至数据库恢复；故障开始和恢复时各通知一次，不按消息重复通知。恢复检查在功能被触发时进行，至少间隔 30 秒；Super User 调用健康检查指令时强制检查。
- 宿主发给 Super User 的私聊通知统一为通知卡片图片：使用宿主消息图片的通知卡片，以 `base64://` 发送，不依赖 RustFS；正文只写原因与影响两行，影响一句话写明，标题块右上只写时间，等级只由状态标与标签颜色表示，页脚左侧为通知种类的英文代号（如 `DB-OFFLINE`）；详细文字以日志为准，绘制失败时退回文字。
- 健康检查是宿主内置运维指令，不属于业务插件；仅 Super User 可在群聊和私聊触发，强制检查数据库与 RustFS，以状态报告卡片图片（`base64://`，绘制失败退回文字）回复数据库、RustFS、LLBot 连接、日志目录占用与已启用的插件（含初始化失败的插件及原因）。
